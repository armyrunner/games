2. Main game logic (pseudocode)
Think of the game as a loop that keeps running until the player loses or quits.

text

START GAME

    SET score = 0
    SET elapsed_time = 0
    SET game_over = false
    SET player_quit = false

    CREATE empty list of falling_letters

    CREATE bottom danger_bar
        DIVIDE danger_bar into sections
        SET each section to OPEN or BLOCKED

    WHILE game_over is false AND player_quit is false

        UPDATE elapsed_time

        IF it is time to spawn a letter
            CHOOSE a random letter
            CHOOSE a random horizontal position
            ADD letter to falling_letters
        END IF

        FOR EACH letter in falling_letters
            MOVE letter downward

            IF player presses the matching letter key
                REMOVE that letter
                ADD points to score
            END IF

            IF letter reaches the bottom
                FIND the danger_bar section it lands on

                IF that section is BLOCKED
                    REMOVE that section's barrier
                    REMOVE the letter
                ELSE
                    SET game_over = true
                END IF
            END IF
        END FOR

        IF player presses ESC
            SET player_quit = true
        END IF

        DISPLAY letters, score, elapsed_time,
                and danger_bar

    END WHILE

    IF game_over is true
        DISPLAY GAME OVER
        DISPLAY final score and elapsed time
    ELSE IF player_quit is true
        DISPLAY GAME QUIT
    END IF

END GAME
3. The three important mechanics
A. Falling letters
Each letter needs a few properties:

Character: the letter, such as A.

Position: its horizontal and vertical location.

Fall speed: how quickly it moves down.

Active status: whether it is still in play.

When the player presses the correct key, only the matching falling letter should disappear and award points.

One rule to decide: if two A letters are falling at the same time, should pressing A destroy the lowest A first? I recommend yes, because it is the closest to danger.

B. The danger bar
Imagine the bottom of the screen divided into 10 sections.

Each section starts as either open or blocked.

A letter landing on a blocked section destroys that section's barrier, and the game continues.

A letter landing on an open section ends the game.

Once a barrier is destroyed, that section remains open for the rest of the game.

This means the danger bar gradually becomes less protective as the game progresses.

C. Score and time
Score: increase whenever a player successfully destroys a letter.

Time: count upward from the start of the game until the game ends or the player quits.

Difficulty: optionally increase the fall speed or spawn frequency as time passes.

4. Build it in this order
Don't try to build everything at once. Work through these milestones:

1. Display the game

Draw the score, timer, falling-letter area, and danger bar. Start with just one letter.

2. Add keyboard input

3. Add falling and random spawning

4. Add the danger bar

5. Finish the game loop

Add the timer, increasing difficulty, ESC to quit, and the final score screen.

2. Pseudocode for each class
Class: FallingLetter
This class represents one letter on the screen. If ten letters are falling, you have ten separate objects created from this class.

text

CLASS FallingLetter

    INITIALIZE
        Choose or receive a letter character
        Receive a horizontal position
        Set starting vertical position at the top
        Set falling speed

    METHOD move
        Increase vertical position based on speed

    METHOD matches_key
        Check whether pressed key matches this letter

    METHOD has_reached_bottom
        Check whether letter reached danger bar

    METHOD draw
        Display letter at its current position

END CLASS
Important design idea: the letter should know how to move and check its own position, but it should not decide whether the entire game is over. The Game class makes that decision.

Class: DangerBar
text

CLASS DangerBar

    INITIALIZE
        Divide bottom of screen into sections
        Mark each section as BLOCKED or OPEN

    METHOD find_section

        Determine which section contains that position

    METHOD hit_section

        IF section is BLOCKED

        ELSE
